# StudentStudies Module Interface

This document defines the public interfaces for the JavaScript service modules. It is the shared contract for implementation and integration. Function names, parameters, return types, and stored fields should not be changed without informing the team.

## General conventions

- All public functions listed here must be exported from their service file.
- `username` is entered by the student and is the unique account/login identifier.
- `courseId` and `taskId` are generated by the system.
- A lookup function returns `null` when the requested object does not exist.
- A command returning `boolean` reports whether the operation succeeded.
- `estimatedDuration` remains `null` when omitted. A fallback duration
  of 2 hours is used only when calculating remaining workload.
- `taskStatus`, `priority scores`, `remaining workload`, and `workload warnings` are derived values and must not be stored in task records.
- Dates are ISO 8601 strings, durations are measured in hours, and progress is stored as one of `0`, `25`, `50`, `75`, or `100`.

## Shared return type

Authentication commands return an `OperationResult`:

```js
{
  success: boolean,
  message: string,
  student: Student | null,
}
```

## `storageService.js`

Provides the common HTTP interface for reading and writing StudentStudies server data.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `get(endpoint)` | endpoint string | `Promise<any>` | Send a GET request and parse the response. |
| `post(endpoint, data)` | endpoint string, data | `Promise<any>` | Send a POST request. |
| `put(endpoint, data)` | endpoint string, data | `Promise<any>` | Send a PUT request. |
| `patch(endpoint, data)` | endpoint string, data | `Promise<any>` | Send a PATCH request. |
| `del(endpoint)` | endpoint string | `Promise<any>` | Send a DELETE request. |

## `authService.js`

Manages registration, authentication, password reset, and the current login session.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `register(studentName, username, password, confirmPassword)` | 4 strings | `OperationResult` | Validate registration input, ensure the username is unique, create a new student record, and store it. |
| `login(username, password)` | 2 strings | `OperationResult` | Authenticate a student and save the current session. |
| `resetPassword(username, newPassword, confirmPassword)` | 3 strings | `OperationResult` | Validate the username, new password, and confirmation, then update the student's stored password. |
| `logout()` | None | `void` | End the current session by removing `studyflow_current_user`. |
| `getCurrentUser()` | None | `Student \| null` | Return the authenticated student or `null` if no valid session exists. |

## `courseService.js`

Manages course records belonging to students.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `createCourse(course)` | `course: object` | `Course` | Validate the input, generate `courseId`, and create a course. |
| `getCoursesByStudent(username)` | `username: string` | `Course[]` | Return all courses belonging to the specified student. |
| `getCourseById(courseId)` | `courseId: string` | `Course \| null` | Return the course with the specified ID, or `null` if it does not exist. |
| `updateCourse(courseId, data)` | `courseId: string`, `data: object` | `Course \| null` | Update only `courseName` and/or `color` while preserving `courseId` and `username`. |
| `deleteCourse(courseId)` | `courseId: string` | `boolean` | Delete the course and all tasks belonging to it. |

### Course creation input

The `course` object contains:

- `username`
- `courseName`
- `color` (optional; defaults to `null`)

The service generates `courseId`. It must not add fields that are not defined in the data contract.

## `taskService.js`

Manages task CRUD operations, progress updates, completion, and task queries.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `createTask(taskData)` | `taskData: object` | `Task` | Validate the input, generate `taskId` and `createdAt`, and create a task record. |
| `getTasksByStudent(username)` | `username: string` | `Task[]` | Return all tasks from courses belonging to the specified student. |
| `getTasksByCourse(courseId)` | `courseId: string` | `Task[]` | Return all tasks belonging to the specified course. |
| `getTaskById(taskId)` | `taskId: string` | `Task \| null` | Return the task with the specified ID, or `null` if it does not exist. |
| `updateTask(taskId, data)` | `taskId: string`, `data: object` | `Task \| null` | Update permitted task fields while preserving `taskId`, `courseId`, and `createdAt`. |
| `deleteTask(taskId)` | `taskId: string` | `boolean` | Delete the task with the specified ID. |
| `updateTaskProgress(taskId, currentProgress)` | `taskId: string`, `currentProgress: number` | `Task \| null` | Update `currentProgress` using an allowed progress value. Task status remains derived and is not stored. |
| `setTaskCompletion(taskId, completed)` | `taskId: string`, `completed: boolean` | `Task` | Atomically complete or reopen a task through the dedicated completion endpoint, preserving prior progress for reopen. |
| `getOverdueTasks(username)` | `username: string` | `Task[]` | Return all incomplete tasks whose deadlines have passed from courses belonging to the specified student. |

### Task creation input

The `taskData` object contains:

- `courseId`
- `taskName`
- `description` (optional; defaults to `""`)
- `deadline`
- `importance` (defaults to `"medium"`)
- `estimatedDuration` (optional; remains `null` when omitted)
- `currentProgress` (defaults to `0`)

The service generates `taskId` and `createdAt`.

Derived values such as `status`, `remainingWorkload`, `urgencyScore`, `importanceScore`, `workloadScore`, `priorityScore`, and workload warnings are not stored in task records.

`currentProgress === 100` is the only definition of completion. `progressBeforeCompletion` and `completedAt` may be stored as transition metadata for Undo/reopen, but they do not define task status.

## `priorityService.js`

Calculates priority-related task values, ranks non-completed tasks, and provides global and local task recommendations.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `getUrgencyScore(deadline)` | `deadline: string \| Date` | `number` | Calculate the urgency score from the time remaining until the deadline. |
| `getImportanceScore(importance)` | `importance: string` | `number` | Convert an importance level into its numeric score. |
| `calculateRemainingWorkload(task)` | `task: Task` | `number` | Calculate remaining workload using the task's `estimatedDuration`, or a fallback duration of 2 hours when it is `null`. |
| `getWorkloadScore(remainingWorkload)` | `remainingWorkload: number` | `number` | Convert remaining workload into its numeric workload score. |
| `calculatePriority(task)` | `task: Task` | `number` | Calculate `0.5 * urgency + 0.3 * importance + 0.2 * workload`. |
| `rankTasks(tasks)` | `tasks: Task[]` | `Task[]` | Exclude completed tasks and return the remaining tasks in priority ranking order without storing calculated values. |
| `getGlobalRecommendation(tasks)` | `tasks: Task[]` | `Task \| null` | Return the highest-ranked non-completed task from the student's tasks. |
| `getLocalRecommendation(tasks)` | `tasks: Task[]` | `Task \| null` | Return the highest-ranked non-completed task from the tasks belonging to one course. |

### Remaining workload

If `estimatedDuration` is provided:

`remainingWorkload = estimatedDuration * (1 - currentProgress / 100)`

Otherwise, the service uses the 2-hour fallback:

`remainingWorkload = 2 * (1 - currentProgress / 100)`

The fallback duration is used only during calculation. The stored `estimatedDuration` remains `null`.

### Ranking order

Completed tasks are excluded from recommendation ranking. Overdue tasks remain eligible for ranking and receive the corresponding urgency score.

Tasks are sorted by:

1. Priority score: descending.
2. Deadline: ascending.
3. Importance score: descending.
4. Created time: ascending.

## `workloadWarningService.js`

Detects workload risk for non-completed tasks and generates warning notifications when a task becomes risky.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `hasWorkloadWarning(task)` | `task: Task` | `boolean` | Determine whether a task meets the workload-warning condition using its urgency and workload scores. |
| `getWarningNotification(task)` | `task: Task` | `WarningNotification \| null` | Return a warning notification for a risky task, or `null` if no workload warning applies. |

### Workload warning rule

A completed task does not receive a workload warning.

An overdue task is displayed as overdue rather than receiving a workload warning.

For other non-completed tasks, a workload warning is shown when:

- `(urgencyScore >= 80 && workloadScore >= 60)`, or
- `(urgencyScore >= 60 && workloadScore >= 80)`.

The service reuses priority-related calculations from `priorityService.js`, including:

- `getUrgencyScore()`
- `calculateRemainingWorkload()`
- `getWorkloadScore()`

If `estimatedDuration` is `null`, the remaining workload calculation uses the 2-hour fallback defined by `priorityService.js`.

### WarningNotification

When a workload warning is generated, the returned object contains:

- `taskName`
- `deadline`
- `remainingWorkload`
- `message`

The warning notification is calculated at runtime and is not stored.

## `studyScheduleService.js`

Generates a recommended study schedule based on ranked tasks and the student's available study time.

| Function | Parameters | Expected return | Responsibility |
| --- | --- | --- | --- |
| `generateStudySchedule(tasks, availableStudyTime)` | `tasks: Task[]`, `availableStudyTime: number` | `StudyScheduleItem[]` | Rank non-completed tasks, allocate available study time to higher-priority tasks first, and return the recommended study schedule. |

### Schedule generation

The service reuses task ranking and remaining workload calculations from `priorityService.js`.

The scheduling process:

1. Exclude completed tasks.
2. Rank the remaining tasks using `rankTasks()`.
3. Retrieve each task's remaining workload using `calculateRemainingWorkload()`.
4. Allocate available study time to higher-ranked tasks first.
5. Continue to the next ranked task while available study time remains.
6. Return the generated list of `StudyScheduleItem`.

The scheduling process does not modify the task's priority score.

### StudyScheduleItem

Each generated schedule item contains:

- `task`
- `suggestedDuration`
- `order`
- `remainingWorkloadAfter`

`StudyScheduleItem` values are generated at runtime and are not stored.

### Scheduling rules

For each ranked task:

- `suggestedDuration` must not exceed the task's remaining workload.
- `suggestedDuration` must not exceed the remaining available study time.
- `remainingWorkloadAfter` is calculated after subtracting the suggested study duration.
- Scheduling stops when no available study time remains or all eligible task workload has been allocated.

## Module dependencies

| Module | May use |
| --- | --- |
| `storageService.js` | None |
| `authService.js` | `storageService.js` |
| `courseService.js` | `storageService.js` |
| `taskService.js` | `storageService.js`; course data when filtering tasks by student |
| `priorityService.js` | Task data passed through function parameters |
| `workloadWarningService.js` | `priorityService.js`; task data |
| `studyScheduleService.js` | `priorityService.js`; task data |

Page scripts and UI components may call service functions and coordinate data between services, but service modules must not directly manipulate HTML elements.
